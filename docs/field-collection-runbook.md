## 1. 目标（PRD-AOI-TWIN-M1 §7-3）

`assets/recordings/` 下沉淀 **≥ 3 个完整班次**的真实产线 `.aotrec`：
- 采集监控面板全程 **0 丢帧**（NFR-04）；
- 每个文件 SHA-256 + 全帧 CRC 校验通过（`AssetTools verify`）；
- 按第 4 节模板登记（设备号/班次/时长/SHA-256）。

## 2. 班前检查（每窗口 15 分钟）

| # | 检查项 | 通过标准 |
|---|--------|----------|
| 1 | 磁盘水位 | 目标盘已用 < 85%（超限录制会自动暂停；预留 ≥ 班次时长 × 0.2GB/班的余量） |
| 2 | 四路适配器连通 | PLC / CAMERA / LIGHT / RESULT_QUEUE 全部「已连接」（采集监控页） |
| 3 | 协议配置 | T2.3 现场配置文件（寄存器映射、SDK 参数）评审冻结版本 |
| 4 | 时钟 | 上位机与设备时间偏差 < 1s（消息时间戳用于 M2 对齐） |
| 5 | 版本 | 部署与 CI 相同版本号的发布构建（Release） |

## 3. 采集执行（每班次）

1. 启动应用 → **采集监控** 页 → 「启动采集」；
2. 确认四路速率与总吞吐稳定（PLC ~20Hz、CAMERA 限频 10Hz、光源 5Hz、结果按拍）；
3. 「开始录制」→ 班次结束（或文件滚动 2h）后「停止录制」；
4. 全程盯守项：**丢帧计数 = 0**、无「源中断」「磁盘水位」告警；
5. 每班次生成一个 `.aotrec`（自动命名 `<设备>_<班次>_<时间>.aotrec`）。

## 5. 班后校验（每文件）

```bash
dotnet run --project src/AoiTwin.AssetTools -- verify <file.aotrec>
# 期望：Footer SHA-256 校验通过、全帧 CRC 通过、帧计数与登记一致（退出码 0）
```

任一文件校验失败：用 `verify <file> --repair` 修复断电截尾文件后重新登记；
修复仍失败则该班次作废重采。
